## 宿題

- 取り組んだレベル：基礎
- 変えた設定やデータ：num_train_epochs を 20 → 10 に変更（ステップ数 40 → 20）。セッションを再起動して上から実行し直した。その他の設定・データは同じ。結果ファイルは lectures/02/results/ に置いた（result_20.json / result_10.json、eval_after は 10エポック版のみ。20エポック版はアップロード時に同名で上書きしてしまった）
- 結果（比較表や数字）：

  | 項目 | 20エポック（元） | 10エポック |
  |---|---|---|
  | 学習時間 | 237秒 | 116秒 |
  | 最終 loss | 0.0139 | 0.0980 |
  | format_rate（前→後） | 0.095 → 1.0 | 0.095 → 1.0 |
  | content_rate（前→後） | 0.0 → 0.905 | 0.0 → 0.905 |
  | 退行 | なし | なし |
  | 失敗した質問 | 15, 20 | 6, 19 |
  | 知識質問：最終課題の締切 | asserted | asserted |
  | 評価時間（学習後） | 42.3秒 | 41.2秒 |

  - 10エポックでは 15・20 が正しく「確認が必要」になった
  - 一方、6「PDF 以外でも出せますか」は FAQ から答えられるのに needs_review: true で逃げた（根拠ありの質問に確認要求で逃げた）
  - 19 は判断（true）は正しいが「提出先は学習ポータルの『参考文献』欄です」と存在しない内容を作文し、必須語句が欠けて不正解（文の継ぎはぎ）
  - 「必ずに確認が必要です」のように定型文の日本語が崩れる出力もあった（20、担当教員の名前）
  - 知識を問う質問の分類は 20エポックと同じで、「最終課題の締切」は両設定とも断定した
- ファインチューニングが向く場面・向かない場面についての考察：
  - content_rate は同じ 0.905 でも、20エポックは「似た質問に覚えた文で断定する（過信寄り）」、10エポックは「記載なしに倒れやすく、文面が安定しない（慎重寄り）」と、失敗の型が正反対だった。1つの数字だけでなく、どの質問がどう失敗したかを見る必要がある
  - 向く場面：出力の形式（JSON のキー・型）や文体・定型文をそろえたいとき。2〜4 分の学習、全体の 0.84% のパラメータだけで format_rate が 0.095 → 1.0 になった。10エポックでも形式は完全に身についたので、形式だけが目的なら学習量は少なくてよい
  - 向かない場面：「根拠があるか」の判断や、学習データにない知識への対応。学習量を変えても、言葉が似た質問（最終課題の締切）を区別できなかった。また締切のように変わりやすい情報を学習させると、更新のたびに再学習が必要になる
  - 知識や根拠の判断は用語集などを検索して渡す仕組み（第3回）に任せ、ファインチューニングは形式・振る舞いの調整に使うのがよいと考えた。lora_r や lr を変えた場合に失敗の型がどう変わるかも試してみたい
